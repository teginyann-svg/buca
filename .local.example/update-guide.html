Après un changement (contenu / fonctionnalités)

Front : page réservation ReactPress kod200.com/buca. API : https://buca.onrender.com (Render).

1. Développer en local

cd ~/Desktop/Reservsalon
npm run dev

UI Vite + API Next. Tester la réservation, semaine, clients, etc.

2. Si l’API a changé

  1. Commit / push du repo si besoin.
  2. Sur Render : redeploy du service buca (ou auto-deploy).
  3. Vérifier https://buca.onrender.com/api/holidays → 200.

Variables : render.env / dashboard Render (pas dans git). Migration one-shot Google : npm run bookings:migrate-google.

3. Build du front ReactPress

cd ~/Desktop/Reservsalon
npm run build

Contrôler le dossier build/ :

  • asset-manifest.json (obligatoire pour ReactPress)
  • static/index-….js + .css
  • index.html + images

Ce lien « marche à suivre » et le dossier .local/ ne sont pas inclus dans build/.

4. Uploader sur WordPress

  1. FTP → wp-content/reactpress/apps/buca/
  2. Supprimer l’ancien contenu de build/ (ou écraser).
  3. Uploader le dossier local build/ (pas un second build à l’intérieur).
  4. Chemin final : …/apps/buca/build/asset-manifest.json
  5. Ne laisser aucun dossier dist/ à côté.

5. Vider le cache WordPress

kod200.com utilise WP Super Cache (+ cache Divi). Sans vidage, l’ancien JS peut rester (404 / page blanche / UI obsolète).

  1. Admin WP → Réglages → WP Super Cache → Delete Cache / Delete Cached Pages (onglet Easy ou Contents).
  2. Divi : Theme Options → Builder → Advanced → Clear (Static CSS / cache), ou menu Divi dans la barre admin si proposé.
  3. Si Cloudflare / cache hébergeur : vider aussi ce cache.
  4. Navigateur : hard refresh Cmd+Shift+R sur kod200.com/buca.

Contrôle Network : le JS ReactPress (static/index-….js) doit être en 200, aligné avec asset-manifest.json (pas un ancien hash en 404).

6. Vérifier en ligne

  1. https://kod200.com/buca/ (hard refresh)
  2. /#/semaine, /#/clients
  3. DevTools → Network : JS ReactPress en 200, appels API Render OK

Rappels

  • Lien local sur la page réservation = fichier dans .local/ (gitignored) + alias Vite en development seulement.
  • Doc déploiement détaillée aussi dans DEPLOY-REACTPRESS.md (celle-ci peut être commitée).
  • Free Render peut dormir : 1ʳᵉ requête API parfois lente.
